## P0 — 즉시 적용 권고 (설계·사이징 결함, 코드 변경 불필요한 것부터)

### P0-1. 리스크 파라미터를 기본값 방향으로 되돌린다

현재 운영값은 거의 전부 "기본값보다 완화"되어 있다. 아래는 즉시(DB 파라미터 값 변경만으로) 되돌릴 것을 권고한다 — **코드 수정 없이 오늘 적용 가능**:

| 파라미터 | 현재 → 권고 | 근거 |
|---|---|---|
| `risk_guard.max_invest_per_stock_pct` | 30% → **10%** | 종목 1개 집중위험을 낮춤. 039종목 평균 투입 10만원대인데 30% 한도는 사실상 무의미하게 넓다 |
| `risk_guard.daily_loss_limit_pct` | -5% → **-3%** | 10/26(-43,797), 11/5(-88,628) 같은 "한 날에 크게 잃는" 사태 조기 차단 |
| `momentum_screen.top_n` | 30 → **5~8** | 신호 품질 집중, 하위권 저품질 신호 배제 |
| `momentum_screen.max_new_per_day` | 50 → **3~5** | 과매매 억제, 종목당 충분한 검토 시간 확보 |
| `momentum_screen.max_flu_rt` | 30% → **15%** | 이미 많이 오른(추격 위험 큰) 종목 배제 범위 복원 |
| `claude_advisor.min_confidence` | 50 → **70** | LLM 2차 거부권의 실효성 복원 |
| `claude_advisor.review_momentum_screen` | 0 → **1** | **가장 손실 큰 전략에 안전장치가 꺼져 있던 상태를 해소** (§2-4 핵심 발견) |
| `fundamentals_filter.pbr_max / per_max / roe_min` | 8·40·2 → **3·25·5** | 재무 부실주 추격매수 차단 |

> 주의: 이 값들은 과거 어느 시점에 의도적으로 완화됐을 가능성이 있다(거래량 늘리려는 시도 등). 되돌리기 전에 **왜 완화했는지 변경 이력**(`algorithm_param_history`)을 한 번 확인하는 걸 권장하며, 특별한 이유가 없다면 기본값 복원이 맞다.

### P0-2. 수동주문도 risk_guard 투입한도 체크를 받게 한다

- 손실의 40%를 차지한 삼성전자 사례(§2-1)의 재발 방지가 **가장 비용 대비 효과가 큰 개선**이다.
- 구현 방향(코드 변경, Edison에게 위임 권장):
  1. **차단형**: 수동주문 접수 시점에도 `risk_guard.check()`의 종목당/전체 투입한도 검사를 통과해야 주문을 전송하도록 주문 경로를 통일한다. (가장 안전하지만 "내 돈인데 내가 맘대로 못 산다"는 체감 제약 발생 — 사용자 의사결정 필요)
  2. **경고형**: 한도를 초과하는 수동주문이 접수되면 즉시 UI/로그에 경고를 남기고, 해당 포지션은 `position_state.entry_algo=NULL`로 표시해 risk_guard/take_profit이 "비표준 대형 포지션"임을 인지하도록 한다(예: 손절 -7%를 그대로 적용하되, 이 종목은 UI에서 별도 하이라이트).
  - 우선 **(2) 경고형**을 먼저 넣고, 반복되면 (1) 차단형으로 전환하는 단계적 접근을 권고한다.

### P0-3. momentum_screen에 "추격 방지" 질적 필터를 추가한다

현재는 당일 등락률×거래량급증 교집합만으로 그 순간 바로 시장가 추격매수한다. 코드 변경이 필요한 핵심 개선:

- **눌림목/재확인 진입으로 전환**: 신호가 뜬 종목을 그 즉시 사지 않고, (a) 다음 캔들/다음 주기에 직전 고가를 재돌파하는지, 또는 (b) 당일 고가 대비 일정 % 이상 되돌림(pullback) 후 반등하는지를 확인하고 진입. 구현은 `screening_result`에 일단 후보로만 기록해 두고, 다음 평가주기에 가격이 추가로 밀리지 않았는지 재검증하는 2-패스 구조가 비교적 적은 코드 변경으로 가능하다.
- **상대강도(RS) 필터**: 같은 날 시장 전체(KOSPI/KOSDAQ 지수) 대비 과도하게 괴리된 단독 급등(테마 announcement성 단발 급등)인지, 업종 전체가 동반 상승 중인지 구분 — 단독 급등은 되돌림 위험이 더 크다.
- 이 개선은 난이도가 있으므로, 당장은 **P0-1의 `max_flu_rt` 하향 + `top_n`/`max_new_per_day` 축소**로 노출을 줄이고, 질적 필터는 P1으로 순차 진행해도 무방하다.

### P0-4. 손절·익절의 구조적 비대칭 완화

현재: 손절 -7% 전량 / 익절 1차 +7~12%에 30~50%만 부분매도 + 나머지는 트레일링. 다음 중 하나(또는 조합) 적용을 권고:

- **(A) 익절 쪽을 더 빨리, 더 많이 확정**: `partial_take_pct`를 7%→5~6%로 낮추고 `partial_sell_ratio`를 50%→60~70%로 올려, "이기는 거래"에서 실제로 손에 쥐는 금액을 늘린다.
- **(B) 손절 쪽을 더 타이트하게**: 현재 -7%도 추격매수 특성상 여전히 크다. P0-3(추격 방지)이 같이 들어가지 않는 한, 손절만 더 조이면 조기 청산→재추격 악순환이 생길 수 있어 **(A)와 함께 적용**하는 걸 권고.
- **(C) 트레일링 스탑 폭 축소**: `atr_multiplier` 3 → 2 로 낮춰 최고가 대비 반납 폭을 줄인다(단, 너무 좁히면 정상적 등락에도 조기 청산되어 승률이 더 떨어질 수 있어 2.0~2.5 구간에서 A/B 비교 권장).

## P1 — 단기(1~2주 내) 개선

### P1-1. volatility_breakout 체결 실패율(83%) — 재시도 폭주 구조부터 고친다

- **코드로 확인된 유력 원인**: `volatility_breakout.evaluate()`는 FAILED로 끝난 신호를 다음 평가주기에 다시 그대로 재생성한다(`ctx.holdings`에 없으면 조건 재검사 없이 또 신호 생성). 돌파 직후 가격이 계속 오르는 종목이라면 "주문가 불일치" 같은 실패 사유가 매 주기 반복되어 FAILED만 쌓이는 구조다.
- **수정 방향**: 같은 (종목, 돌파조건) 신호가 최근 N분 내 FAILED로 끝났으면 쿨다운 동안 재시도하지 않도록 `signal_log`/`position_exit_state` 성격의 짧은 캐시를 둔다. 또는 실패 시 `return_code`를 보고 "재시도해도 될 사유"와 "재시도 의미 없는 사유"를 구분해 후자는 즉시 그날 재시도 금지.
- 이와 별개로 `event_log`/`api_error_log`에서 FAILED 34건의 실제 `return_code`/`return_msg`를 뽑아 가설을 최종 확인한다.

### P1-2. macd_cross에 추세·제로선 필터 추가

- 현재는 교차 1개 조건만으로 매수해 횡보장 휩쏘에 취약하다(§2-8).
- 추가 권고 필터(둘 다 또는 택1):
  - **제로선 필터**: MACD 라인이 0선 위에서 교차할 때만 유효 신호로 인정(0선 아래 교차는 하락장 중 일시 반등으로 신뢰도가 낮아 제외).
  - **장기 추세 필터**: 주가가 자신의 60일 또는 120일 이동평균 위에 있을 때만 교차 신호를 인정(이미 `ma_cross_filter` 알고리즘이 존재하므로, macd_cross 신호에도 이를 연동하는 방식을 검토).
- 현재 거래 비중이 작아 당장 손실에 끼치는 영향은 적지만, 이 전략의 비중을 늘리기 전에 선행되어야 하는 보강이다.

### P1-3. 상장폐지·관리종목 전환에 대한 보유 중 재점검

- 신규 진입은 `universe_filter.exclude_warning=1`로 걸러지지만, **이미 보유 중인 종목이 사후에 관리종목·거래정지로 전환**되는 경로에 대한 조기 경보가 없다(040670 사례, §2-7).
- `stock_master.state`/`order_warning` 값이 변경되는 시점을 감지해, 보유 종목이 경고군으로 전환되면 즉시 알림(가능하면 거래정지 전 선제 매도 신호)을 내는 모니터링 로직 추가를 권고.

### P1-4. averaging_down 파라미터 재검토 또는 폐기

- `drop_pct=15%`가 risk_guard 손절선(-7~10%)보다 훨씬 더 떨어져야 발동해, 사실상 죽은 기능이다(§2-6).
- 둘 중 하나로 정리: (a) `drop_pct`를 손절선보다 타이트하게(예: 5%) 당겨서 "손절 전에 1회 물타기로 평단을 낮춰볼 기회"를 실제로 작동시키거나, (b) 의도적으로 쓰지 않을 거라면 UI에서 비활성화하고 문서에 "현재 미사용" 명시.

## 신규 제안 — 중장기 투자용 알고리즘 `trend_position` 도입

손실원인 분석(§5)에서 확인했듯, 현재 3개 진입전략(momentum_screen·volatility_breakout·macd_cross)은 **전부 수일~당일 단기 매매**이고 공통적으로 "짧은 시계열 신호 1개"에만 의존한다. 계좌 전체가 100% 단기 트레이딩 축으로만 구성돼 있어, 승률이 낮을 때 이를 상쇄할 "느리지만 꾸준한" 수익원이 없다. 이를 보완하는 **4번째 진입전략**을 신규 제안한다.

### 설계 개요

| 구분 | 기존 3개 전략 | `trend_position`(신규 제안) |
|---|---|---|
| 신호 근거 | 당일/단기 지표 1개(등락률, 돌파, 교차) | 장기 이동평균 추세 + 펀더멘털 품질 |
| 평가 주기 | 실시간/매 사이클 | 일 1회(종가 기준)로 충분 |
| 목표 보유기간 | 수일 이하(돌파는 당일) | 수주~수개월 |
| 포지션당 금액 | 10~30만원(소액 다건) | 30~50만원(소수 고확신) — risk_guard 한도 내 |
| 손절 | 평단 대비 -7~10%, 즉시 전량 | 추세 이탈(종가가 장기선 하향 이탈) 기준, 구조적 손절 |
| 익절 | 부분(30~50%)+ATR 트레일링 | 추세 유지 중엔 보유, 추세 이탈 시에만 전량 정리(승자를 더 오래 태움) |

### 구체적 진입/청산 규칙(제안)

1. **대상군**: 기존 `universe_filter`/`fundamentals_filter` 재사용(코드 재사용 가능) — 다만 PBR/PER/ROE/부채비율은 **기본값 수준 이상으로 엄격하게**(momentum_screen류의 "싼 게 비지떡"과 달리, 중장기는 재무 품질이 승률에 직결).
2. **진입 신호**: (a) 60일 이동평균이 120일 이동평균을 상향 돌파(골든크로스, macd_cross보다 훨씬 느린 주기라 휩쏘 적음) **AND** (b) 현재가가 진입일 기준 120일선 위에서 **최근 3거래일 이상 연속 유지**(단발성 돌파 배제, 추세 확인). 이 두 조건의 동시 충족으로 macd_cross의 §2-8 약점(제로선/추세 미확인)을 구조적으로 피한다.
3. **일 신규진입 한도**: 낮게(1~2개/일) — 저빈도·고확신 전략이므로 momentum_screen처럼 넓게 살 필요가 없다.
4. **손절**: 종가 기준 120일선을 하향 이탈하면 전량 매도(퍼센트 고정 손절이 아니라 추세 구조 자체가 깨졌다는 신호). 짧은 기간의 노이즈성 하락은 견딘다.
5. **익절**: 고정 % 부분익절 대신, **주간(週) 단위 저점**이 높아지는 동안은 보유, 직전 주간 저점을 종가가 깨면 전량 매도(스윙 하이/로우 트레일링) — 추세가 꺾이기 전까지는 수익을 깎지 않고 태운다. take_profit.py의 ATR×3 로직(일 단위, 추격형에 맞춰진 폭)보다 훨씬 느슨한 주기를 쓴다.
6. **risk_guard와의 관계**: 이 전략으로 진입한 포지션에는 기존 risk_guard의 -7% 즉시 손절을 **그대로 적용하면 안 된다** — 중장기 포지션은 정상적인 등락에서도 -7~10% 되돌림이 자주 발생하기 때문이다. `risk_guard`가 `entry_algo`별로 다른 손절 규칙을 적용할 수 있도록 하거나(코드 확장 필요), 이 전략의 종목은 risk_guard의 일반 손절에서 제외하고 위 4번 규칙만 적용하는 예외 처리가 필요하다 — **구현 시 가장 주의할 지점**.

### 기대 효과

- 승률·손익비 구조가 다른 "독립적인 수익원"을 하나 추가해, 단기 전략군의 저승률 구간을 상쇄.
- 평가주기가 일 1회라 거래빈도·수수료가 낮고, 시스템 전체의 과매매 성향을 완화.
- 다만 **이 전략의 유효성도 실데이터 없이는 장담할 수 없다** — P3의 백테스트 인프라가 갖춰진 뒤, 소액(예: 월 투입한도 50만원)으로 먼저 실거래 검증하는 단계적 도입을 권고한다.

## P2 — 중기 개선 (포지션 사이징·분산)

- **변동성 조정 사이징**: 모든 신규 진입이 고정 `buy_amount`(10~30만원)인데, 변동성이 큰 종목(일일 등락 10%+)과 작은 종목에 동일 금액을 넣는 건 위험 노출이 종목마다 다르다. ATR 기반으로 "위험 1단위당 투입금"을 맞추는 사이징(예: 계좌의 0.3~0.5%를 손절폭으로 나눠 수량 결정)을 고려.
- **종목/업종 집중도 제한**: 현재 동시 보유 종목 간 업종·테마 상관관계를 보지 않는다. 동일 테마 급등주 2~3개를 동시에 담으면 개별 종목 손절이 몰리는 날(10/26 10종목, 10/13 6종목 동시 손절)이 반복될 수 있다 — 업종당 동시 보유 한도 설정 권고.
- **전략별 성과 분리 대시보드**: `daily_trade_summary`에는 algo_code가 없어, 이번 분석에서 종목별 손익과 `orders.algo_code`를 수동으로 매칭해야 했다. `daily_trade_summary`에 대표 `entry_algo` 컬럼을 추가하거나, 웹 대시보드에 "전략별 실현손익/승률" 뷰를 추가하면 다음부터 이런 분석을 매번 수동 SQL 없이 상시 모니터링할 수 있다.

## P3 — 장기 (검증 체계)

- **백테스트 인프라**: 지금은 파라미터를 바꾼 뒤 실계좌에서 결과를 보는(=이번처럼 사후분석) 방식이다. `price_daily`가 이미 쌓이고 있으므로 momentum_screen/macd_cross/volatility_breakout에 대한 과거 데이터 기반 백테스트를 붙여, 파라미터 변경 전에 승률·손익비를 사전 검증하는 루프를 권고.
- **Walk-forward 재튜닝 주기화**: 월 1회 정도 최근 데이터로 파라미터(특히 momentum_screen의 등락률/거래량 임계값)를 재검토하는 정기 프로세스화.

## 요약: 지금 당장 바꿀 3가지 + 중장기 축 1가지

1. **P0-1 파라미터 원복**(DB 값만 변경, 당일 적용 가능) — 특히 `claude_advisor.review_momentum_screen=1`, `momentum_screen.max_flu_rt=15`, `risk_guard.max_invest_per_stock_pct=10`.
2. **P0-2 수동주문 경고 로직**(005930처럼 한도 초과 수동매수 재발 방지) — Edison에게 구현 위임 권장.
3. **P0-4 익절 비율 상향**(`partial_take_pct`↓, `partial_sell_ratio`↑) — 이기는 거래에서 더 많이 확정해 손익비(현재 0.37)를 개선.

이 세 가지만 적용해도 §1의 기대값 계산(승률 35%×익 3,510 − 65%×손 9,451)에서 분모(평균손실)와 분자(승률·평균수익) 양쪽을 동시에 건드리게 되어, 구조적 마이너스 기대값에서 벗어날 가능성이 가장 크다.

4. **(중장기 축) `trend_position` 신규 도입**: 위 세 가지가 "지금 있는 단기전략의 손익비를 개선"하는 것이라면, 이것은 "**단기 매매 하나에만 기대지 않는 구조로 포트폴리오를 바꾸는 것**"이다. momentum_screen·volatility_breakout·macd_cross 3개가 전부 수일 이하 보유·단일 단기지표 의존이라는 공통 약점(§5)을 가진 상태에서, 승률 개선만으로는 한계가 있다 — 보유기간·신호근거가 완전히 다른 축을 하나 더 두는 쪽이 장기적으로 더 안정적인 해법이다. 다만 백테스트 없이 바로 실자금 전면 투입은 위험하므로 소액 단계적 검증(P3 선행 권고)으로 시작한다.
